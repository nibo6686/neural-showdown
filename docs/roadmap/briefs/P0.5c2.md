> **Slice P0.5c2 — move authority-dependent tests from raw restore to born sessions.**
> Repo: `C:\Users\cloud\Downloads\neural\final`, branch `main-native11`
> (after P0.5c1). Read `AGENTS.md` (no delegation, no full suites) first.
>
> **Problem.** About 336 failing tests (P0.2 causes: "old raw/constructed
> snapshot helper lacks native11 occurrence-bound restore authority", "legacy
> item episode helper overrides `resetWithOptions` with a raw serialized
> snapshot", and "module setup witness passes raw snapshot without restore
> ticket"). They build a state by hand, serialize it, and restore it into an
> **authoritative** environment, because they check identity, owner knowledge,
> held restore or publication. Native11 correctly refuses that: a raw
> snapshot can't prove identity. The P0.5a simulation-only mode doesn't help
> these tests, because they need authority.
>
> **Approach: the established born-session pattern** (see
> `tests/native_owner_knowledge.test.ts` "P48 constructed initial effects…"
> and `tests/helpers/owner_selection_restore.ts:constructed`):
> 1. Inject exact teams by overriding `Teams.generate` for the session's
>    creation only, restoring it in `finally`.
> 2. Create a real `PipelineIntegrationSession` (or authoritative
>    `LocalBattleEnv`). Identity and original-owner facts are **born**, not
>    restored.
> 3. Reach the target state by **scripted legal choices**, using the
>    canonical-action helpers (`choice`, `joint`). Use team design to make
>    states reachable: levels, Belly Drum, Super Fang, Substitute, hazard
>    setters, Trick, and similar.
> 4. Held restore inside these tests uses the real ticket path
>    (`captureSeededSnapshot` → `prepareRestore` → `resetFromSerialized(…,
>    ticket)`), never a raw snapshot.
>
> Put this in a shared helper, `tests/helpers/born_session.ts`. Its interface
> is `bornSession({teams, seed, options})` plus `playTo(session, steps)`.
> Migrate file by file through it, so later tests are short.
>
> **Order** (largest and most registry-relevant first): `pipeline_episode`,
> `item_identity`, `request_knowledge*` (TS and Python),
> `perspective_knowledge_source` (TS and Python), `active_request_restore`,
> `illusion`, `item`, `soak`, `env_manager`, `request_delivery_ledger`,
> `pipeline_integration`, then the mechanics files with authority sections
> from the P0.5a "A" list (wish, healing_wish, roost, future_sight, revival,
> entry_hazard, screen, court_change, singlemove, public_stages,
> spirit_shackle, forced_switch, and so on).
>
> **Rules**
> - Assertions stay byte-identical. Only setup changes. If a state is
>   genuinely unreachable by legal play on the pinned engine, don't fake it:
>   - move the test to simulation-only, if authority isn't actually what it
>     asserts; or
>   - retire it with a one-line reason, for example "state unreachable in
>     gen9randombattle on b8f23c99: <why>".
> - No new `src` seam that lets constructed state become authoritative.
>   If you think one is needed, stop and describe it in the report instead.
> - Keep each test fast. A scripted battle should be a handful of turns, not
>   a long episode.
