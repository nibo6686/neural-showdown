> **Why this comes first.** Under the native11 profile, the observable-state
> validator rejects 10 protocol families: `-start`, `-end`, `-sidestart`,
> `-sideend`, `-weather`, `-fieldstart`, `-fieldend`, `cant`, `heal` and
> `-swapsideconditions`. They're listed in `protocol_contract_b8f23c99.json` as
> `recognized_unsupported_commands` with kind `unproved_semantic_family`, and
> `observable_state.ts:validateRawProtocolRecord` has an extra blanket throw:
> `Native11 candidate effect/lifecycle semantics unproved`. **178 of the 198
> real probe replays (90%) contain at least one of these**: hazards, weather,
> terrain, Substitute, volatiles, `cant`. So on the main-line engine, the
> extractor fails on almost every realistic battle. This is the source of the
> `added_types`, `transform_types` and `public_stages` R items, and of the flaky
> `env_manager` test (6/8 runs fail). It probably also explains many tests
> classified authority-dependent in P0.5a. All ten families were supported and
> reviewed under 0.11.10; native11 quarantined them pending a re-check that
> never happened. The other ten unsupported tokens (`status`, `curestatus`,
> `clearstatus`, `-clearstatus`, `nothing`, `copyboost`, `invertboost`,
> `endability`, `-endability`, `swapsideconditions`) were also unsupported
> under 0.11.10. Leave them as they are.

> ### Part 2 — stop hiding root causes
> `LocalBattleEnv.markError` (`env_manager.ts`) turns any consumer error into
> `settling/v1/simulator-error`, which hides the cause, such as
> `Unsupported raw protocol event: -end.`. Keep the code, but carry the
> underlying message, error class and the first stack frame inside the
> settling failure `diagnostic` (for example `cause: {name, message, at}`), and
> make sure test failures print it. Don't change error codes that tests match
> on.
>
> ### Part 3 — deterministic tests
> Tests that use `controller: 'random'` without `random_seed` are
> nondeterministic. `env_manager`'s
> `canonical submissions reject stale actions before raw choice forwarding`
> passed in P0.4 by luck. Give every test-side random controller an explicit
> `random_seed`, using the existing `createSeededRandom` path. Grep
> `sim-core/tests` and `trainer/tests`, and list the changes in the report.
> This only changes test setup; assertions stay unchanged. Don't change the
> production default.
