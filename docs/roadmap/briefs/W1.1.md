> **Why first.** 29,404 corpus battles reproduce exactly, but today they run
> only in **simulation-only** environments, which have no knowledge
> authority. So they can't be used to check perspective-knowledge (K) facts
> or to produce K-labeled data. A replay's input log contains everything
> needed to create a **born** authoritative session: the battle seed, each
> player's team seed, and every choice. Running replays through the real
> pipeline makes the whole corpus a correctness oracle for every Phase 1
> workstream and the dataset source for Track B. This is the core of W8,
> moved forward.
>
> ### Part A — `replaySession(replay)`
> 1. Create a `PipelineIntegrationSession` (the authoritative, owner-knowledge
>    path) that the engine **births** from the replay's `>start` battle seed
>    and the `>player` team seeds. Teams must come from the engine's own
>    generation from those seeds, exactly as on the server. **No
>    `Teams.generate` override and no restore.** If the session API can't
>    take player seeds today, add a minimal, explicit creation option. Seeds
>    are ordinary creation inputs, not authority.
> 2. Step through the recorded choices. Map each `>p1 …` / `>p2 …` input
>    command to the **canonical legal action** at that boundary. A choice
>    that doesn't map to exactly one legal action fails that replay with a
>    reason; don't guess.
> 3. **Oracle check:** the session's spectator log must match the public
>    replay log exactly, using the same normalization as `tools/replay_repro`.
>    A born session that diverges is a failure, never admitted.
> 4. Expose the battle's owner-addressed decision boundaries, each with both
>    owners' K projections and the human's chosen canonical action. This is
>    the shape Track B will consume. No dataset writing yet.
> 5. Add `tools/replay_repro --born` with the census worker pattern (worker
>    threads, per-replay outcomes, fail-soft). Run it over the **admitted**
>    corpus and record the born-session pass rate in `benchmarks.md`. Size the
>    timeout from a 500-replay pilot, and skip the known-long cases rather
>    than run into a timeout.
>
> ### Part B — K differential on the corpus (the oracle for every workstream)
> Add `--born --kdiff`. At every decision boundary, compare each **adopted**
> registry row's projected fact (`knowledge-coverage.json`, `status: adopted`)
> against the simulator's truth, restricted to that owner's legitimate
> knowledge. Rules:
> - an adopted `known` fact must equal the truth;
> - an `unknown` value is never a mismatch;
> - a fabricated value where the registry says unknown **is** a mismatch.
>
> Report mismatches by registry row. **Target: 0** across the admitted
> corpus, for the 25 currently adopted rows. A mismatch means an adopted
> claim is wrong: diagnose it, and demote the row if it can't be fixed in
> this slice.
