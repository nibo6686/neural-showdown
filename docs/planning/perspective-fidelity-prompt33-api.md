# Prompt33 snapshot admission and compatibility

Active engine: 0.11.10; native11 remains unadopted. No portable import, version certificate, schema change, snapshot identity change or new birth/source authority.

`snapshotRestorePolicy(packageVersion)` is a finite policy decision: 0.11.10 legacy; 0.11.11 held-b2-required; other versions reject unsupported-runtime. `assertBeliefForkPolicy` rejects the target. These pure functions accept strings for PRE policy tests and convey no runtime ownership or reconstruction authority. Runtime callers derive the version solely from their internally owned checked profile; no client/RPC selector is added.

`NativeObjectAssociation.assertRestoreAdmission(environment, serialized, ticket)` is a read-only check of existing authority. It requires an enabled live controller, its exact pending candidate/ticket, current committed parent and serialization entry, the exact held simulator-state root with unchanged references/content, and no prior input enrollment/reconstruction. It never tolerates missing/disabled authority for target admission. Copies, sibling/foreign entries, altered state and late tickets cannot import. Subsequent existing beforeRestore/acceptRestore/prepareCommit checks remain unchanged.

Target `LocalBattleEnv.resetFromSerialized` checks admission at its first executable statement, before occurrence rotation, original/birth abandonment, disableLegacy, cloning, terminal/override probes, retirement, fromJSON or restart writes. A standalone env without association rejects raw-restore-unsupported. Session prepareRestore explicitly checks the same held chain before entering reset, including on old B2 session continuation. Old authority-free legacy reset still uses its previous path; reconstruction never creates B1 birth.

Target manager/RPC belief fork rejects before source serialization, view building, team sampling, donor construction, env ID allocation or map mutation. Direct buildBeliefSnapshot adds an optional internally owned runtime profile (default acquired internally); ownership and policy validate before clone/sampling. Copied descriptors do not authorize this helper. Server dispatch remains unchanged and inherits the manager restriction.

Managed live seeded references use unchanged wire fields and snapshot/transition IDs. The existing private manager map now holds the actual env object and an opaque world/reset occurrence alongside the held snapshot. Opaque handle strings retain `snapshot-<digits>` syntax with a random per-manager decimal namespace, so a restarted manager cannot accidentally recycle a prior address. JSON copies may address an existing held entry; they cannot create one. Environment occurrence accessors are trusted in-process plumbing, not wire or B2 authority.

All native choice writers rotate the occurrence immediately before stream.write, including automatic/retry choices. Reset, error, destroy and close rotate synchronously. Manager reset/close/closeAll remove access before awaiting cleanup. Valid preflight rejection leaves the occurrence/handle intact. Any write or post-write failure invalidates prior entries; successful seeded execution consumes env entries and stores a fresh output entry in the new occurrence. Stale retained map values cannot be retrieved through admission and are pruned on store or cleanup. This supplies no rollback claim after live writes. Existing serializer validation-only probes remain distinct from adopting a reconstructed live world; no B2 handle is minted by manager stepping.

New errors: snapshot-admission/v1/{unsupported-runtime,belief-fork-unsupported,raw-restore-unsupported}; native-association/v1/restore-admission-mismatch. Existing ticket/parent/snapshot/ownership and live handle errors remain. Historical errors and literal identity algorithms stay unchanged.
