# Prompt28/B2 private restored-object association

Candidate infrastructure only. B1 historical birth holds and B2 current object associations are distinct. No indexed event, carrier, source registry, Python bridge, K-fact, publication or completeness adoption.

## Authority chain and independently held material

1. B1 privately retains the actual creation environment/Battle and owner unpacked-set references. Its trusted producer transfer `captureBirthObjects` maps each original set reference to the native Pokemon object, with unique complete object coverage and original Side.team reference order. It accepts only the exact birth environment/Battle and staged/active controller; it does not reconstruct originals from sets.
2. At the existing env `captureSeededSnapshot` call, the actual `serializeBattle()` object is checked while those authoritative objects exist. Serialized current-order row `.set` must be the exact live Pokemon.set, and native team encoding must agree with the independently held object→original-slot map. Current position is a serializer index, not identity authority. The existing structured clone then produces a snapshot occurrence whose root, sides, rows and set references are privately retained together with an independent full value copy.
3. The existing transition builder changes the authoritative snapshot root (and forced-switch builder clones state). An explicit env handoff preserves the held serialization occurrence/object map onto that actual builder result, checking source occurrence and state transfer. No identity algorithm or builder output changes.
4. The committed association holds the exact accepted parent boundary and snapshot object. `prepareRestore` requires both references and unchanged snapshot root/row/set references plus full contents. A copied/sibling/foreign snapshot or parent cannot authorize reconstruction even if its labels, contents and fingerprints match.
5. At the actual env reconstruction seam, the native-only final clone is registered immediately before `Battle.fromJSON`. The two existing validation-only reconstruction probes are not enrollment seams. After the actual call, fresh objects must be disjoint from prior objects; Pokemon.set must equal the registered final input row set; Side.team[held original slot] must equal that same reference. Both owners validate before restart, request reemission or actions. Original values remain solely in independent B1/Prompt23 evidence.
6. After actions, serialization captures the reordered party using the same reconstructed object identities. Both-owner commit preparation requires that candidate's exact ticket, native world and captured output snapshot. Commitment occurs synchronously alongside delivery/session swap. Rejecting a candidate discards preparation before awaited cleanup, retaining the exact committed parent/handles/evidence.

The pinned `sim/state.ts` assigns `state.set = pokemon.set` in serialization and `pokemon.set = state.set` in deserialization. Snapshot and restore clones break equality with the prior live sets, so identity is joined through the held serializer/clone occurrence; it is never inferred from copied values. Hash/label/value checks supply transport integrity only, not authority. Input row/set replacement with equal-valued copies rejects.

## API, privacy and lifetimes

`getNativeObjectHolding(owner)` returns a frozen empty process-local handle for the current committed association. `readNativeObjectHolding(handle, owner)` returns frozen `{owner, original, original_slots, observation_id, branch_id, step_index}`. `original` is the exact independently retained owner evidence; `original_slots` is that owner's proven current party order, as immutable original one-based slots. There is no native object/set accessor, caller mapping input or arbitrary roster resolver. No opposing original/controller, seed or native token is exposed by this API or added to existing wire/diagnostics.

Wrong-owner, copied, JSON/structured-cloned and foreign handles reject. Successful replacement creates new owner handles and invalidates old current handles. Returned frozen metadata remains data. B1 historical holdings continue separately. A failed candidate preserves current handles/evidence; its restore/preparation tokens cannot be read or reused after discard. Same-label sessions have independent parent/snapshot/handle identities.

Initialization failure revokes current and tentative association state before awaited env cleanup. Restore failures discard candidate state; they do not revoke the committed parent. Session close revokes all association access synchronously before cleanup. Closing the current env directly revokes current association; retiring the replaced env does not revoke the new current env's association. Legacy initial authority-free restore disables the controller, preserves operation, and exposes no B1/B2 handles. Candidate restore never invokes B1 birth observation or regenerates original facts.

Producer controller methods are trusted in-process machinery held in session/env ECMAScript-private fields, not public arbitrary-input authentication factories or a sandbox against monkeypatching native methods. Matching values cannot impersonate a real session's private reference chain. No transported metadata is source authority. Historical snapshots retain their previous privileged native-set/seed semantics and exact bytes; this work adds none of its private pointers to them.
