# Prompt27/B1 private native birth API and lifetime

Candidate only, awaiting independent review and lead acceptance. This is historical native creation enrollment, not current roster resolution, restored mapping, indexed events, source registry adoption, K facts or completeness.

`PipelineIntegrationSession.getNativeBirthHolding(owner)` returns a frozen empty process-local owner handle after successful native creation. `readNativeBirthHolding(handle, owner)` requires the exact addressed handle of that session and returns frozen `{owner, original, slot_count}`. `original` is the exact independently retained Prompt23 owner evidence object, not a reconstructed unpacked/snapshot set. Both-direction wrong-owner, copied, transported and same-label foreign-session handles reject. There is no native-set accessor, token serialization, set→slot resolver or restored-object accessor. Existing wire/result/view/snapshot/diagnostic shapes do not gain B1 fields.

Internally `NativeBirthEnrollment` holds the exact `OriginalOwnerCreation` reference and binds once to the initial environment. Candidates receive neither creation nor birth controllers. Its ECMAScript-private rows retain the actual preconstructor set references in unpacked order and distinct submitted-owner occurrence references. Original values/presence stay in the frozen Prompt23 evidence; mutable native sets are never frozen, used to regenerate originals or exposed by the API.

## Trust boundary and actual call path

The env's existing producer-owned BattleStream subclass calls a per-instance observer immediately after actual `>start` creates the native Battle and before either `>player`. Native `setPlayer` is wrapped to scope the exact owner/options object and a fresh private occurrence. Native `getTeam` calls the original unpacker, then enrolls that actual returned reference array before Side/Pokemon constructors. The callback must have the exact environment, Battle, owner, options and occurrence references, with no side constructed yet. The submitted packed string must equal the already-held owner submission; equality only corroborates this actual scoped producer call. It cannot construct an original controller/handle or authenticate a transported certificate.

The trusted producer class is not an arbitrary-input certification factory or sandbox against monkeypatching the actual native stream/controller. A test-created controller or handle cannot impersonate the real session's ECMAScript-private controller. No registry accepts this metadata as source authority.

Both owner arrays must enroll once, be nonempty/complete, have unique set references and share none across owners. The observer detaches after the second actual player command; initialization failure also detaches. Activation validates each native Side.team reference against the captured array and each unique Pokemon.set reference against that owner array. It also requires the exact original evidence now held by the activated Prompt23 creation.

## Lifetime and atomicity

`new → observing → staged → active → invalid`. The initial environment is bound in new. Native observation starts only once, before construction. Neither owner has a usable handle while either is tentative. Session creation settles, snapshots and validates the initial boundary, activates original retention and commits the existing delivery ledger; only then does B1 validate both enrollments and activate together before create returns. Any birth/source/boundary/ledger/activation failure revokes all birth, original and delivery authority before awaited environment cleanup.

Instance wrappers are removed after submission, even on errors. Missing/duplicate/misrouted/late/foreign/submission-mismatched enrollment invalidates tentative authority. Wrong-owner/forged read attempts reject without revoking a legitimate active holder. Repeated resets cannot reuse the one-shot native controller.

Initial env retirement aborts only staging; active historical birth evidence remains session-held through successful and rejected candidates. It says nothing about the new native objects in a restored candidate. Session close revokes B1 synchronously, before async cleanup and regardless of cleanup success. Previously returned frozen metadata remains data, not a live capability. Handles become unreadable.

The accepted legacy initial unstarted restore abandons the bound controller in new, returns the historical session without originals/delivery/birth authority, and continues to operate. Standalone env reset/restore has no birth controller. Candidate restore never invokes the birth observer and cannot mint a new birth. B2 mapping is explicitly unsupported.

Errors use `native-birth/v1/` reasons: invalid-owner, duplicate-environment, foreign-or-duplicate-creation, late-observer, duplicate-or-late-submission, submission-mismatch, missing-enrollment, unscoped-or-late-unpack, foreign-or-late-enrollment, duplicate-enrollment, post-construction-enrollment, invalid-set-occurrence, not-staged, constructor-association-mismatch, unavailable, foreign-or-forged-holding, restore-cannot-mint-birth. Existing session closed errors retain `pipeline/v1/closed`.

Historical raw engine snapshots already contain engine state, including sets/seeds. This boundary adds no B1 native references, tokens, seeds or opposing-original evidence to them; existing snapshot/wire bytes are preserved. It does not reinterpret snapshot privacy or grant original authority from those values.

## B2 prerequisites retained

B2 requires separate lead authorization, independently held B1 provenance, exact accepted parent/candidate snapshot continuity, native serialized order encoding and a proven restored reference association. It must cover reordered actual sessions, same-label sibling/foreign/copied parent negatives, both-owner isolation, candidate rollback and cleanup. It cannot revive revoked birth handles or create original values from mutated sets. B3 indexed causal events, B4 resolver/source adoption, Python authority, Prompt21 carrier binding and strong fidelity remain later boundaries.
