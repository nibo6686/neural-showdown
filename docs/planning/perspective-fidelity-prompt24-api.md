# Prompt24 private request trace API

`LocalBattleEnv.getRequestEmissionTraceHandle(owner)` returns a held, opaque owner token. `inspectRequestEmissionTrace(handle, owner)` returns a frozen array of frozen `RequestEmissionReceipt` rows; receipt objects are frozen too. Neither serialized copies nor the diagnostic `producer_occurrence` token grant inspection authority.

Each row contains `owner`, process-local `producer_occurrence`, global environment-local 1-based `emission_index`, owner-local 1-based `owner_emission_index`, `origin` (`native_emission` or `restore_reemit`), literal `request_record`, literal `request_json`, and `receipt: {owner_receipt_index, record, json}`. Exact text means the strings carried by the pinned native transport, without trimming, parsing or reserialization. Equal text produces separate rows.

The per-instance BattleStream `_write` scopes synchronous native emissions; explicit restoration `side.emitRequest` calls scope only their synchronous producer invocation as reemission. `pushMessage` observes before fanout. ManagedPlayer joins each request before tracker consumption, trimming and JSON parsing, using its captured owner-stream reference and producer FIFO. Native side requests can precede public updates: these indices are not public cursors.

Receipt/provenance failures invalidate the entire trace, clear queued/joined data and revoke handles. Pending receipts block inspection of either owner with `request-trace/v1/unreceived-emission`; they do not expose a partial supported trace. Forged/foreign handles fail without revoking legitimate handles. Errors are ordinary Error values with `request-trace/v1/` prefixes. Reasons include invalidated, invalid-owner, invalid-stream-enrollment, unsupported-origin, non-synchronous-producer, unsupported-owner, unsupported-producer, multi-record-request, foreign-receipt-stream, missing-or-duplicate-emission, receipt-order-or-text-mismatch, unbound-owner, foreign-or-forged-handle and unreceived-emission. Environment access without a live trace rejects as unavailable.

Destroy/reset invalidates before awaiting disposal. Failed initialization or restoration after environment retirement clears access. Restore validation rejected before retirement preserves the running environment and its existing legitimate trace; it creates no replacement trace. A new stream occurrence gets new tokens even if local counters and text repeat. Already returned frozen diagnostic rows remain data, not live authority. Terminal/requestless boundaries add no invented emissions; restoring terminal request history cannot mint freshness. Restored wait/force/revival requests are reemissions; later actual native actions get independent native rows.

The trusted pinned native FIFO and held owner streams are assumptions. Identical bytes alone cannot detect arbitrary same-byte injection, substitution or reordering inside a monkeypatched stream. This is not an arbitrary in-process security boundary. The internal producer controller is trusted wiring, not a certificate accepted from callers.

Existing results, views, snapshots, diagnostics, boundaries and bundles carry no trace fields. No session committed sequence, causal prefix/observation join, current request authority, identity crosswalk, source registry, Python authority bridge or knowledge fact is adopted. S01c-2b must independently select/join/commit evidence before environment retirement; environment-local counters are insufficient across candidates.
