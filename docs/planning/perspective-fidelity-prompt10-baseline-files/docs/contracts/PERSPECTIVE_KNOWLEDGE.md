# Perspective knowledge v1 — PK-01 normative candidate

Status: exact local contract candidate for lead review, 2026-10-10. No runtime, profile eligibility, publication route or schema adoption. Prompt 8 lead decisions D01–D07 govern. `fixtures/perspective-knowledge-v1/schema.json` is the exhaustive wire type/key/nullability definition; this document supplies normative semantics and ordering. Both must pass review together. Existing observable v1/v2, belief and DATA canonical bytes/IDs and `faithful_complete_episode` retain their meanings.

## Wire and limits

There are two explicit entry schemas: `perspective-knowledge/v1` privileged audit and `perspective-knowledge-consumer/v1` trusted local validator output. `kind` is a closed discriminator; all object keys are required and extra keys reject. Null is allowed only at explicit nullable keys. Empty arrays are explicit, never missing families or absent source authority. UTF-8 JSON has Unicode scalar values; reject invalid UTF-8, duplicate JSON keys, lone surrogates, nonfinite values, fractions in integer fields and booleans as integers. No Unicode normalization. Only ASCII schema keys; strings ≤256 Unicode scalars, public raw lines also ≤256 for this bounded v1. Integers 0..2147483647 unless signed stage -6..6. Reject beyond limits, never truncate. At most 4096 entries per dictionary/table, 4096 lines per source/prefix, 6 roster/crosswalk slots, 4 starting moves, 32 proofs per fact, 20 family verdicts, 2 owner bindings. Total encoded audit ≤16 MiB, nesting ≤32; reject cyclic/infinite traversal. Larger histories require another reviewed version.

`schema.json` defines every object: origin, source, prefix, evidence, certificate, fact, starting, current, request, knowledge, profile, verdict, boundary, binding, audit and projection, and nested set/value/crosswalk/obligation rows. These are independent schemas, not additions to old observations. `profiles.json` freezes the only three candidate profile manifests and their content IDs. `property-types.json` exhaustively freezes every property to allowed known value tags; prose examples do not override it. `property` must belong to its K family. Known fact values use only the closed typed value union. HP is integer exact or interval public bucket. All intervals require min≤max. `effect.remaining` is null or an interval value (no recursive effects). Subjects/source_subject are closed non-capability identities `p1|p2:side`, `:roster:1..6`, `:appearance:N` or `:roster:R:move:1..4:incarnation:N`; they never designate files/URLs/store keys. IDs/types, applicability and precision cannot be inferred from coercion.

Submitted sets preserve original source array order with 1-based `slot`, distinct from future party positions. Each nullable submitted field means the provider explicitly observed omission, not unavailable source. Empty item is submitted absence. Nature omitted is known absence of a submitted named nature, with neutral stat modifier; never invent Hardy. EV/IV tables preserve zero. Raw generated arrays require immutable deep copies before packing. This wire retains only the enumerated PokémonSet fields; unsupported additional owner-submitted fields block eligibility, never silently discard them. Imported arbitrary formats/sets are unsupported in this version.

Every content-addressed table array is unique and sorted ascending by ID. Facts referenced in a context are sorted by ID. Witness lists/exclusions/writers are unique lexically sorted except record indices (unique ascending). Profile obligations and verdicts are ordered K01..K20. Boundary bindings are exactly `[p1,p2]`. Roster/move order and source/prefix records preserve delivery order, never sorted. Crosswalks unique by appearance, lexically sorted. Sets ordered slot1..N, contiguous. Compact map keys equal value IDs and expand into the exact sorted arrays before any semantic check. Identical repeated content is one entry; duplicate entries reject, even if identical.

## Source authority and original provider

Trusted local validator input is not self-authenticating JSON. It receives an independently held origin registry and immutable addressed-delivery registry from the local creation owner. A `source_type`/provider label, matching hash, producer receipt, packed control input or imported registry cannot grant authority. No signing/receipt framework is introduced. Imported projection acceptance is unsupported.

Proposed `addressed-team-provider/v1`: the local `LocalBattleEnv` creation owner generates the team arrays, retains a deep immutable copy of **each owner's own** generated array, addresses that owner's delivery, binds `origin`, owner, delivery sequence0/cursor0 and `before_effects`, and finishes delivery before the `>start`/`>player` payload write. It retains a privileged association to the exact packed submission; this association is local validator source evidence, not consumer transport or permission to expose the other team. Provider implementation does not yet exist. Engine/mutable-state snapshots, seed reads, first requests and post-effect hidden reads cannot stand in for it. Current source seam: env_manager.ts:683–692; all players present can start immediately in PS battle.ts:3155–3187,1863–1887. A missing required registry entry means missing original authority; classify incomplete, not complete.

## Facts, persistence and replay

Known facts require typed nonnull value, reason `none`, evidence and exact/interval/bucket precision. Known_absent has null value/reason none and affirmative source proof. Unknown has null value, an enumerated reason, precision not_applicable; cannot assert absence. Inapplicable has null value, proved_rule_inapplicable, explicit rule evidence. No free-text reasons. Freshness immutable only in original context; current versus last_known is explicit. Omitted PP/disabled/trapped does not mean0/false; retained values need retained source proof and stale marking. Requests never persist as actionable across wait/requestless/terminal or restore without a fresh addressed request; waiting request has actionable false. Replay request is always null. Fact observed_at uses **delivery cursor or exclusive indexed public-prefix count**, not turn number; request source also carries independent sequence. Prefix record indices are 0-based; evidence observed at index+1. Preserve exact same-turn order.

Starting snapshots are immutable. Discovery requires revision=N+1, parent old starting ID, same origin/owner/policy and retained facts except an explicit unknown-to-proved refinement; old snapshot/proofs remain in audit. Logical fact key is (owner,subject,family,property,effect_key); each context has at most one fact per key. Child retains every prior key, replaces only unknown with supported known/known_absent, and cannot modify prior proved values. Old unknown snapshot stays reachable through parent; it is not duplicated alongside its replacement in the new snapshot. Full replay source change creates another source ID and new starting revision, never mutates existing source or chronology. An owner-only retrospective crosswalk lives in `starting.crosswalk` as appearance→roster with original-possession certificate. It is not copied into current state or used to relabel earlier appearances/dynamic facts. Public chronology uses `p1:appearance:N` or independently current-proven roster identities, never future starting crosswalk inference. Starting fact subjects must belong to the perspective owner; public current subjects may belong to either side.

`effect_key` is required nullable text. It is null for non-effect properties; for known effect values it equals the exact source/rule-normalized `value.data.name` (no case/alias guessing). Named effects/side conditions/pseudo-weather/pending intent coexist as separate logical facts; Reflect and Spikes cannot overwrite each other. Null key on an effect property denotes whole-collection unknown/absence/inapplicability, not an unnamed known effect. Whole-collection known_absent cannot coexist with a known named member. Named member known_absent requires lifecycle proof. Collection completeness requires exhaustive relevant writer/identity coverage; observed members alone cannot imply all others absent. `effect-collection-canary.json` contains independently ledger-backed simultaneous Reflect/Spikes for both perspectives as a structural subset, explicitly unsupported for aggregate runtime assurance.

Replay `public-replay-owner-starting/v1` uses full indexed source solely for owner's original-possession certificates, starting facts and crosswalk. Per certificate: exact source, subject/property, witnesses, complete scan bounds [0,N), relevant finite writer inventory and exclusions for transfer/copy/called/Transform/acquisition/ambiguous identity. Genuine never reveal/ambiguous carrier stays unknown. Unsupported relevant writer yields unsupported assurance; do not call it ambiguity. Ordinary move execution alone is insufficient until the complete supported continuity scan excludes acquisition/copy/called origins. Transfer itself supplies no original proof; Prompt8 EX04 T0 independently proved recipient Leftovers. Consumption can prove original item only under unmodified uniquely attributable continuity. Late owner original reveal is available in starting projection at origin, but observed_at retains actual witness cursor. Opponent/current facts remain prefix-causal. Future full-source IDs/certificates must not occur in chronological subdocument bytes, public proofs or identity domains.

## Identity and proof joins

All new IDs are `sha256:` plus 64 lowercase hexadecimal digits. Exact preimage is UTF8(`pk/v1/` + kind + LF) concatenated with canonical JSON of the **entire object excluding only its top-level id**. Canonical JSON: recursive ASCII-key lexical order, no spaces, decimal minimal integers, booleans/null literals, UTF-8 scalar strings with only mandatory JSON escaping (control chars lower-case hex; quote/backslash escaped; slash literal); arrays retain normative order. No BOM, final LF or normalization in preimage. Transport may be pretty JSON; IDs use canonical bytes. Floats/exponents and negative zero are invalid. This independent bounded integer/scalar contract does not alter old canonicalization. identity-vectors.json gives concrete UTF8 hex+expected digest for every object domain plus Unicode.

Origin contains public battle key, exact rules and format, never engine env_id or seed. Prefix ID binds origin, parser and eligible records only; never full replay source ID. Evidence original may bind full replay source; evidence public binds only matching public_prefix source and prefix ID; evidence request binds owner request and causal delivery prefix. All evidence shares origin. Every fact reference resolves, its owner matches context, its source is legitimate and scope matches use. Request evidence may survive as stale current owner fact but never expose opposite source. Public evidence.source records must equal evidence.prefix records. Every index is within source records. Certificate witnesses resolve and match owner/subject/property/scan/writer policy; source and origin closure are required. No source reference cycles.

Current IDs bind origin, owner, prefix, cursor, previous current and facts. Starting IDs bind origin, owner, policy, original source/revision parent/facts/crosswalk. Request IDs bind origin/owner/delivery/source/prefix/actionability/facts. Knowledge ID binds all three contexts and boundary index/policy/owner. No circular boundary ID reference inside knowledge. Verdict ID binds knowledge and exact required profile/families/result. Boundary ID binds origin/index/cursor/type/parent/restored_from and both owner joins to knowledge/verdict and old observation/belief/actor record IDs. Actor record ID is null for nonactor; require actual legacy validation if present. Stand-in fixture legacy IDs are only isolated join vectors, not executable DATA rows.

`binding` is the exact publication/history join row: origin/owner, consecutive input_index/successor_index, input/successor knowledge IDs, input/successor old observation IDs, nullable input/successor belief IDs, nullable transition and actor_record IDs. Exactly one per owner per consecutive boundary pair, even for nonactors. IDs must equal their boundary owner rows. If actor_record is nonnull, transition is nonnull and the independently legacy-validated record supplies these exact observation/belief/transition IDs, owner and corresponding state-history prefixes; actor_record equals successor boundary actor_record_id. If nonactor, both actor_record/transition null; no invented DATA row. Belief IDs require actual legacy belief/history validation, not lookup by digest alone. Audit closure carries these rows plus immutable old objects in the caller's separately validated legacy envelope; old wire objects are not embedded or redefined here. This explicit trusted caller argument is required before publication, and fixture stand-ins exercise joins only. Ordinary input/successor proofs use the full closure too.

First boundary index0/parent null; successive index+1 and nondecreasing cursor. Both owners' current cursor/prefix matches boundary. Knowledge boundary/index, verdict knowledge/profile and owner joins match. Current parents must be the immediately preceding same-owner context; no history forks/grafts. Origin closure includes original context and required source registries; terminal-only or wrong-battle history cannot grant origin. Restoration binds exact preceding original boundary via restored_from, retains starting/proof identities and causal prefix/current parent; terminal remains requestless. Continuing restored sessions needs the same original delivery registry, history and fresh request authority as uninterrupted control.

Audit forms share exact semantic closure: full carries contiguous origin→target history and both owner contexts at every boundary; ordinary carries one target plus **the same sufficient origin/parent proof closure**, including nonactor evidence (no terminal-only shortcut); compact carries equivalent dictionaries expanded before shape/reference/owner/privacy/assurance checks. This v1 ordinary form intentionally is not a space-saving segment. Audit ID binds schema/form/origin/required_profile/target and complete tables, including privileged replay source. No unreachable extra entries or external resolvable references. Multiple original revisions must lie on a used context parent chain. No unresolved restoration handles. One bad binding rejects the entire wrapper before output.
