## Integration testing gap analysis (review-plan-tests)

Critical before identity coding:

1. B1 helper-only tests cannot prove production enrollment. Require red missing factory/callback evidence, then actual session call path before effects, with independent owner raw evidence and paired fault injection.
2. B2 source order encoding cannot prove held-parent legitimacy. Require reordered real-session restore and sibling/foreign/copy negatives at the same production commit seam. The present reference model cannot satisfy this gate.
3. B3 writer hooks alone cannot prove selected-prefix causality. Require native writer→emitted update→spectator routing→admission→committed owner history→appearance relation. Unknown/log-mutated events must reject rather than fallback. Real split/duplicate/filter tests must precede resolver adoption.
4. B4 cannot inherit semantic authority from structure or transported references. Require actual resolver caller and owner-only observable assertion; source adoption/bridge/publication remain separate scopes.

Per-boundary checklist: local reference/lifetime unit checks; actual native session wiring; integrated rollback/restore route; realistic generated-input case plus separately labeled mechanics; exact semantic negative before any identity relation escapes; independent reviewer with literal expectations. No model/checkpoint or broad corpus eval is relevant to this bounded native source proof. Each boundary must return for review before the next starts. Do not patch the existing Prompt26 instructions or aggregate implementation plan.

## Independent-review gate corrections

The independent reviewer identified required gates before B1–B3 APIs are implemented:

- **B1 privacy:** both-direction wrong-owner handle/read rejection at enrollment and active holding; serialization, ordinary observable output and diagnostics must not expose the other owner's raw team, set/object tokens or seed. Repeat after initialization failure and close. Handle swapping is a semantic negative, not just a label check.
- **B2 privacy/rollback:** both-direction cross-owner reads on reconstructed mappings reject before association escapes. After restore rejection, only unchanged committed addressed mappings are readable; candidate references cannot be retrieved or serialized. Check both owner outputs against hidden-opponent perturbations and absent internal mappings.
- **B3 privacy/atomicity:** in a real session candidate, capture a supported actor/index relation and prepare its sidecar, then inject a failure after capture/preparation and before the existing synchronous commit. Assert exact committed event-history/capability references remain unchanged for both owners, tentative candidate tokens are unreadable/revoked, and valid retry obtains a fresh occurrence with its own native→public→normalized relation. Add both-direction wrong-owner event-handle/read negatives and serialization/observable absence at emission, successful commit, rejected candidate, restore and close. Existing Prompt23/25 rollback cannot satisfy this new sidecar gate.

These are mandatory red/green tests within B1/B2/B3, not deferred privacy work in B4. The current source tests characterize hooks; they do not test APIs that do not exist. Transform evidence now compares the actual captured birth-set/actor.set reference and its starting moves through Transform/reentry. Restore evidence no longer asserts unobserved birth callbacks; future B2 must observe the actual production birth factory seam before reconstruction to prove that restoration cannot mint a birth capability.
